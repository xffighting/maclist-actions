# MacList 文件上传对话框流程规格

版本：0.3.0 Native Preview

状态：默认自动确认桥接与本机静默门禁已完成；标准面板和真实应用可视化回归暂停

更新时间：2026-07-15

## 1. 一句话目标

用户在微信、邮件或其他应用中打开 macOS 文件选择窗口后，MacList 自动贴附搜索栏；用户输入客户名、项目名、文件名或路径片段，从候选清单选中文件。默认模式在严格安全核对后确认原单文件 Open 面板，使附件进入待发送区；绝不自动发送。日常流程不要求额外快捷键、不打开 Finder、不切到另一个应用、不依赖剪贴板。

## 2. 首次设置（只由用户发起）

MacList 私有本地索引默认关闭。没有用户选择，就没有 MacList 文件夹扫描。

1. 启动 MacList，从菜单栏按 macOS 正常流程允许“自动唤起”和“控制当前文件窗口”。MacList 不绕过 TCC。
2. 点击 **选择索引文件夹…**。
3. 在系统 `NSOpenPanel` 中选择一个或多个具体资料文件夹。整个系统、整个用户目录、普通 Library、系统目录等宽根目录会被拒绝。
4. 用户确认后，MacList 创建这些文件夹的持久化 macOS 书签，并在后台建立有上限的本地索引。
5. 菜单显示明确状态：未设置、正在建立、已就绪、部分完成、需要更新、需要重新选择文件夹或操作失败。

文件窗口完成模式默认是 **选中文件后自动确认原窗口**。用户可以在 MacList 菜单关闭这一项，切换为“只选中、手动确认”；偏好在后续启动中保持。

只持久化：

- 文件名；
- 完整路径；
- 修改时间；
- 所选文件夹的 macOS 授权书签与授权版本。

不读取或保存文档正文、缩略图、文件内容和聊天/邮件信息。完整路径本身可能包含客户名和项目名，因此索引与书签放在权限收紧的本机私有应用数据中。

用户可以随时：

- 点击 **立即更新本地索引**，重新扫描仍然有效的授权文件夹；
- 点击 **重新选择索引文件夹…**，用一组新授权替换旧授权；
- 点击 **清空本地索引…**，删除元数据缓存和书签，但不删除任何原文件。

只有用户点击设置菜单时，MacList 才可能暂时激活自身以显示文件夹选择器，并在结束后尝试回到之前的应用；这不是日常上传流程的一部分。

## 3. 日常使用流程

1. 用户在微信或邮件中点击“上传文件 / 添加附件”。
2. macOS 文件选择窗口出现。
3. MacList 自动发现真实文件面板进程；只有证据达到文件窗口阈值时，才把非激活搜索栏贴附在原窗口附近并取得输入焦点。
4. 用户输入客户名、项目名、文件名或路径片段。
5. 候选清单即时显示文件名和父目录。用户用方向键或鼠标选中候选。
6. 用户按回车。MacList 收起浮层，在原文件窗口中定位并精确选中同一个文件。
7. 默认模式下，MacList 只在安全策略允许时确认原 Open-file 面板；附件进入微信或邮件的待发送区域，但 MacList 不点击“发送”。

自动确认只允许：原会话仍是当前会话、精确选择已核对、窗口是单文件 Open 面板，并且默认按钮明确表示“打开 / 选择文件 / 添加附件 / 上传文件”。Save、选文件夹、未知类型、多选窗口、旧会话、未核对选择、按钮缺失或按钮含义不唯一时都拒绝自动确认，原窗口保持打开，用户手动处理。菜单关闭自动确认后，回车始终只选中文件。`Esc` 只关闭 MacList 浮层，不关闭或提交原文件窗口。

## 4. 搜索来源与结果规则

MacList 使用双来源、元数据限定的搜索：

1. **本地索引是主来源**：只搜索用户授权文件夹中的文件名和完整路径，支持用客户目录或项目目录找回文件。
2. **Spotlight 是补充来源**：查询 macOS 已有系统索引中的文件名、路径和时间元数据。即使 MacList 私有索引未设置，Spotlight 仍可能提供候选，但不能保证覆盖全部文件。
3. 两个来源返回相同路径时，本地索引记录覆盖 Spotlight 记录。
4. 每次输入生成新的查询代次；索引刷新也生成新的本地结果代次。旧查询、旧刷新和已取消任务不能覆盖当前候选清单。
5. 查询为空、对话框关闭或上下文切换时，旧结果与异步任务失效。

## 5. 本地索引生命周期与安全门禁

### 启动

- 未保存授权：状态为“未设置”，provider 为空，不扫描。
- 已有授权和缓存：只有授权版本、规范化根目录集合均匹配时才加载缓存。
- 授权存在但缓存缺失或不匹配：状态为“需要更新”，不在启动时偷偷重建。
- 书签损坏、文件夹失效或根目录不再可信：清空当前 provider，状态为“需要重新选择文件夹”。

### 建立与更新

- 先解析书签，再执行宽根目录策略和规范化去重。
- 建立前捕获根目录物理身份，建立后再次核对；目录被替换时，本次结果作废。
- 扫描有文件数、访问项数和时间上限，跳过隐藏内容、包后代、符号链接和非普通文件。
- 文件上限、访问上限、根目录不可访问、子目录枚举或元数据读取失败时，安全取得的结果可以保存和搜索，但状态必须是“部分完成”。
- 更换授权、取消、清空或新一轮建立都会递增 generation；旧任务结束后也不能重新写回缓存。

### 清空

- 先让运行中的建立任务和旧 generation 失效；
- 清空内存 provider；
- 删除授权书签和索引缓存；
- 原文件始终不在删除范围内。

## 6. 明确不做

- 不在日常流程中打开 Finder、Cling、微信、邮件或其他目标应用。
- 不通过 `NSWorkspace.open` 打开命中文件。
- 不复制文件或路径到剪贴板作为主流程。
- 不读取文件正文、聊天内容或邮件内容。
- 不自动选择联系人、收件人或聊天，不点击发送。
- 不自动提交 Save、选文件夹、未知类型或多选窗口，不覆盖文件；只允许确认满足完整安全条件的原单文件 Open 面板。
- 不把 GPL 项目 Cling 的源码复制进本仓库。
- 不宣称所有自定义上传窗口都兼容。

## 7. 技术基线与模块边界

- Swift 6、AppKit，macOS 13 及以上。
- 菜单栏常驻原生应用，无第三方运行时依赖。
- `hostPID`、`dialogOwnerPID`、运行时键盘目标 PID 和 `generation` 分开建模，不能互相代替。
- 每个实际文件面板 PID 拥有独立 `AXObserver`；不支持通知时才使用低频只读轮询。
- 常驻循环只比较轻量焦点快照；深层 AX 分类在专用串行队列执行。
- 当前不注册全局启动快捷键。
- 搜索窗口是非激活式 `NSPanel`；日常流程不调用 `NSApp.activate(ignoringOtherApps:)`。

```text
MacListApp
├── DialogProcessDiscovery   系统焦点与独立 Panel Service 发现
├── FileDialogMonitor         文件窗口生命周期、双 PID 与代次
├── FileDialogDetector        多证据评分与当前窗口保存
├── SearchPanelController     贴附搜索、双来源合并与旧查询拒绝
├── LocalIndexCoordinator     用户发起的选择、更新、清空和状态同步
├── FileDialogBridge          精确文件交回与可取消的完成事务
└── AccessibilityPermission  系统权限检查与明确引导

MacListCore
├── AuthorizedFolderStore     书签、授权版本与私有原子存储
├── LocalIndexRootPolicy      宽根目录、嵌套目录和规范化边界
├── LocalIndexRootIdentity    建立前后的物理目录身份核对
├── LocalIndexService         默认关闭、缓存接受与 generation 门禁
├── LocalFileIndexer          有上限的元数据扫描
├── LocalIndexProvider        主搜索源
├── SpotlightProvider         补充搜索源
├── SearchResultSet/Epoch     去重、优先级与旧结果门禁
├── DialogSelectionPreference 默认自动确认与菜单只选中偏好
└── DialogSelectionPolicy     输入校验和失败关闭的确认策略
```

Apple 从 macOS 10.15 起让 Open Panel 由独立进程绘制，外部应用不能直接取得宿主的 `NSOpenPanel` 对象。因此回填采用受控的辅助功能桥接：保存原窗口 → 收起浮层 → 等待原窗口自然恢复焦点 → 触发“前往文件夹” → 写入绝对路径 → 精确回读选中项 → 重新核对会话、窗口类型和唯一默认按钮 → 在策略允许时确认。任何证据不足都停在原窗口，由用户手动确认。

## 8. 权限与失败语义

### 辅助功能或文件窗口控制未授权

菜单明确显示需要的系统权限。MacList 保持安静，不绕过 TCC，不静默修改系统设置。

### 本地索引未设置

显示：`先从 MacList 菜单选择要搜索的客户/项目文件夹。`

Spotlight 补充候选可能仍可见，但不得暗示私有索引已建立。

### 部分索引

显示“部分完成”及安全取得的文件数、文件夹数。结果保持可搜索，并提供“立即更新本地索引”；不得显示成“已就绪”。

### 自定义或不兼容窗口

显示：`这个上传窗口暂不支持自动选择；原窗口没有被关闭或修改。`

### 自动确认被拒绝

Save、选文件夹、未知类型、多选窗口、旧会话、精确选中未核对、默认按钮缺失或含义不唯一时，不执行最终确认。原文件窗口保持打开，并显示：`已选中文件；为确保安全，请在原窗口手动确认。`

### 文件失效

显示：`文件已移动或删除，请重新搜索。`

任何失败都不得关闭、提交原窗口或打开其他应用作为隐式兜底。桥接开始后的目录、选择或焦点状态可能保留，真实恢复行为必须等可见回归后再作承诺。

## 9. 静默测试策略

### 本地索引与搜索门禁

- 默认关闭：没有授权时 provider 为空，不触发扫描。
- 授权版本：缓存 `rootRevision` 与书签授权版本不同即拒绝。
- 根目录集合：缓存根目录与书签解析后的规范化路径集合不同即拒绝。
- 根目录策略：系统根、用户根、普通 Library、系统目录、符号链接逃逸和过多根目录被拒绝。
- 根目录身份：建立期间目录被替换时，结果不得持久化或发布。
- generation：更换文件夹、清空或取消后，旧建立任务不能复活缓存。
- partial：文件上限、访问上限、不可访问根目录、子目录枚举或元数据访问错误只能发布“部分完成”。
- 双来源：相同路径以本地索引为准，来源清空互不污染。
- stale query：上一条查询和刷新前的本地结果不能覆盖当前候选。
- 隐私：测试确认索引文件不包含样本文档正文。

### 文件窗口与桥接门禁

- 中文、英文、大小写、宽字符与子序列模糊匹配。
- 文件名命中优先于路径命中；修改时间只作同分因素。
- 目录和空路径不能进入桥接；候选路径不预读文件正文，若目标已缺失，原文件面板无法形成精确单选证据，因此不会自动确认。
- 状态机不会在没有已捕获对话框时提交文件。
- 文件面板 PID 即使不同于微信/邮件宿主 PID，也进入独立观察链。
- MacList 搜索框取得焦点时，不误判原窗口关闭。
- 多窗口、多屏、负坐标和部分离屏布局保持在可见区域。
- 对话框关闭或切换后，旧对话框 generation、桥接任务和回调全部取消。
- 默认偏好是 `selectAndConfirm`；菜单可持久切换为 `selectOnly`。
- `selectAndConfirm` 只有在当前会话、精确选择、单文件 Open 面板和唯一明确的文件动作按钮同时成立时才包含最终确认。
- Save / folder / unknown / multi-select / stale session / unverified selection / missing-or-ambiguous button 都拒绝确认并回退人工。
- `selectOnly` 计划始终不包含最终确认动作。

上述自动确认门禁已由本机统一验证入口通过；GitHub 完整 XCTest 以本次推送后的 Actions 为准。这里的“静默通过”只表示纯策略、一次性会话凭证、构建和事务门禁通过，不代表标准 `NSOpenPanel`、微信或邮件兼容性已经可视化验收。

所有自动化测试只使用临时沙盒目录和合成文件名，不扫描用户真实资料文件夹。

## 10. 可视化回归顺序

### 标准 `NSOpenPanel` Harness

1. 用户明确允许前台测试后，打开 Harness 的系统文件选择窗口。
2. 验证 MacList 自动贴附、直接取得输入焦点和候选清单。
3. 输入测试客户/项目/文件路径，按回车。
4. 默认模式确认原面板自动完成，Harness 收到同一文件 URL；消息发送不在 Harness 范围内。
5. 逐项构造 Save、选文件夹、未知类型、多选、旧会话、未核对选择、缺失按钮和歧义按钮，确认它们全部保留原窗口、回退人工。
6. 关闭菜单自动确认后，验证只选中文件，必须由用户点击“打开”。
7. 确认日常流程中 Finder 和 MacList 主应用没有被激活到前台。

### 真实应用

- 微信：聊天窗口 → 上传文件 → 搜索 → 回车 → 精确选中并确认原 Open-file 面板 → 附件进入待发送区；不自动发送。
- Apple Mail：新邮件 → 添加附件 → 搜索 → 回车 → 精确选中并确认原 Open-file 面板 → 附件出现；不自动发送。
- Outlook：新邮件 → 添加附件 → 搜索 → 回车 → 精确选中并确认原 Open-file 面板 → 附件出现；不自动发送。

每个场景记录 macOS 版本、应用版本、窗口类型、是否成功和失败阶段。当前三者均为“待验证”。

## 11. 构建和验证命令

```bash
swift build --package-path app
./app/Scripts/all-smoke-tests.sh
swift test --package-path app
./app/Scripts/build-app.sh release
./app/Scripts/verify.sh
```

本机只有 Command Line Tools 而缺少 XCTest 时，至少运行全部 framework-free smoke harness 和 release 构建；GitHub Actions 在完整 Xcode runner 上执行 XCTest。

## 12. 发布门槛与待实测问题

- 主路径中不存在 Finder 打开、应用切换、剪贴板注入、目标应用启动或自动发送。
- 标准 `NSOpenPanel` Harness 完整通过；在用户允许可见测试前保持未验证状态。
- 微信、Apple Mail、Outlook 逐个真实回归；通过前不写兼容承诺。
- 辅助功能未授权、索引未设置/部分完成、文件不存在、桥接超时等失败均可见且不破坏原窗口。
- 自动确认拒绝矩阵完整通过；无法证明是当前、精确、单文件 Open 面板和唯一明确文件按钮时一律回退人工。
- README、中文文档、验收记录和 Apple 风格 Dashboard 同步展示真实通过项与待验证项。
- 每次推送都继续以 GitHub Actions 对应提交的实际结果为远端门禁；只有全绿后才允许考虑新 tag、GitHub Release、签名和公证。
- 默认自动确认不改变“永不自动发送”；任何真实应用未通过都必须保留为兼容性未验证。
